# Figure specification

All figures for `manuscript_v1.tex`. Every entry states what the figure must show, how it is
built, and how to check it. The source of truth for the paper is
`docs/paper/manuscript_v1.tex`; the figures are separate standalone documents compiled to PDF
and included with `\includegraphics`.

## 0. Build system

| item | value |
|---|---|
| engine | `pdflatex` (MiKTeX 25.x) |
| figure class | `\documentclass[tikz,border=4pt]{standalone}` |
| output | one-page PDF per figure, included at `width=\textwidth` (or `0.92\textwidth`) |
| directory | `docs/paper/figs/` |
| raster assets | 300 dpi PNG, generated by `_scratchpad` scripts from real dataset files |

Build a figure:

```
cd docs/paper/figs
pdflatex -interaction=nonstopmode fig_arch.tex
pdftoppm -png -r 150 -singlefile fig_arch.pdf fig_arch_preview   # visual check
```

Build the paper: `pdflatex manuscript_v1.tex` twice from `docs/paper`.

## 2. Typography

| element | size |
|---|---|
| node text | `\footnotesize` in Fig. 1, `\scriptsize` in Figs. 2 and 3 |
| edge / dimension labels | `\scriptsize` |
| panel headers | `\small\bfseries` |
| tensor shapes | always in `$\mathbb{R}^{...}$` inside the node, second line |

Rule: a figure included at `0.75x` must still print at 6 pt or larger. Check by rendering the
standalone at 150 dpi and reading it, not by assuming.

## 3. Pseudo-3D conventions

Blocks are drawn as extruded cuboids, not flat rectangles: a front face plus a top and a right
side face offset by a fixed depth vector.

| parameter | value | note |
|---|---|---|
| depth vector | `(2.2mm, 2.2mm)` | constant for every block, so the eye reads one light direction |
| top face | same fill as front, lightened with `black!12` overlay | |
| right face | same fill, darkened with `black!22` overlay | |
| draw order | side, top, then front | front face must occlude the far edges |
| text | front face only, never on a 3D face | keeps type horizontal and readable |
| arrows | always drawn on the front plane, never on a 3D face | |

The intent is depth cues, not photorealism: shadows, perspective vanishing points and camera
rotation are deliberately out of scope. Anything that would make an arrow change direction in
depth is forbidden, because the reader is meant to follow the data flow, not a scene.

## 4. Figure inventory

### F1, architecture (`fig_arch.tex` -> `architecture.pdf`, label `fig:arch`)

Two horizontal bands, one flow left to right.

* **Student band** (solid arrows): occupancy thumbnail -> occupancy encoder -> fusion ->
  GCLCT -> two decoders -> design and parameter outputs. Parameters and spectra enter the
  fusion from the left; `c` and `a` are separate small nodes so their two distinct uses are
  visible.
* **Teacher band** (dashed): full occupancy -> EMA occupancy encoder carrying the frozen
  spectral FiLM -> targets `z_y^spec, z_y, z_y^sc` -> latent losses. A separate "all
  parameters known" input feeds the EMA scalar MLP, so no dashed line has to cross a student
  box.
* The input panels are **real held-out samples**, not placeholders.

Checks: every arrow starts and ends on a node anchor; no arrow crosses a box; band frames do
not clip labels; both thumbnails are the same sample so the student/teacher contrast is honest.

### F2, block internals (`fig_blocks.tex` -> `blocks.pdf`, label `fig:blocks`)

Three panels stacked vertically as rows, each flowing left to right.

* (a) occupancy encoder: image -> `4x4` stride-4 conv -> `R^{256x192}` -> six blocks, each
  `LN -> MHSA -> (+) -> LN -> MLP -> (+) -> FiLM`; residuals are circles with bypass arrows
  from the sub-layer input, not separate boxes.
* (b) fusion: three token groups -> concat `R^{273x192}` -> two blocks with the same residual
  convention.
* (c) one GCLCT block: `LN+FiLM(c) -> self-attn -> (+) -> LN+FiLM(c) -> cross-attn(kv=273) ->
  (+) -> LN+FiLM(c) -> MLP -> (+)`, braced `x8`.

Checks: bypass arrows must not overlap the main path; the three outer token arrows must step
around the middle token box; panel headers sit above their rows.

### F3, symmetry (`fig_sym.tex` -> `unitcell.pdf`, label `fig:unitcell`)

Real held-out sample only.

* (a) recorded `64x64` occupancy `G`.
* (b) the `32x32` quadrant `Q`.
* (c) the reflection `(c)`, verified `np.array_equal(G, rebuild) == True` before plotting.

Checks: the assertion runs at asset-generation time; the caption states the measured equality
rather than asserting it rhetorically.

### F4, masks (`masks.pdf`, label `fig:masks`)

Three rows: what each evaluation regime hides. Generated from the evaluator's own
`BlockMasker(seed=999)`, so the figure cannot drift from the protocol.

### F5, designs (`designs.pdf`, label `fig:designs`)

Five rows: truth, pure inverse, partial, retrofit, released baseline. Produced by the
evaluation script, not redrawn by hand.

## 5. 3D unit cell (planned, `fig_unitcell3d`)

Purpose: replace the flat parameter schematic with a perspective drawing of one meta-atom.

* substrate slab (semi-transparent), pillar (cylinder or rounded prism), dimension arrows for
  `l` (lattice pitch), `h` (pillar height), `r` (pillar radius).
* 3D is limited to this figure: an isometric or oblique projection generated by script, then
  included as PDF. No hand-placed coordinates that cannot be regenerated.

Status: **Asymptote blocked.** `asy` reports 2.88 and `mpm` says the package is installed, but
any file fails with `recursive loading of module 'plain'` from `plain_constants.asy`, i.e. the
binary and the shipped `.asy` sources are mismatched. Until MiKTeX is repaired, the 3D unit
cell is drawn in TikZ with a fixed oblique projection: x-axis right, y-axis up,
depth axis at `(0.5, 0.35)`.

## 6. QA checklist (run before every commit)

1. `pdflatex` the standalone: zero errors, one page.
2. Render at 150 dpi and look at it: no overlapping labels, no arrow through a box, no
   clipped node.
3. In the paper: `\includegraphics` count equals the figure count; no `multiply defined`
   labels in the log.
4. No em dash anywhere in the source (`---`, `--` for ranges, or U+2014).
5. Tensor shapes present for every tensor-carrying output.
6. Any figure that makes a factual claim (symmetry, masks, designs) is generated from the
   dataset or the evaluator, never drawn by hand.
